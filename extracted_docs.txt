●  Allows  precise  vehicle  identification  using  unique  model  codes

Fault Assessment Calculator — ユーザーストーリー（テンプレ準拠・改訂版）
【前提】
・テンプレ構成は「User Story Template」に準拠。
・課題／エピックは「Product Owner Candidate Exercises – Fault Assessment Calculator」を参照。
Epic A：認定基準の検索と基本過失割合の算出
Goal：事故状況に合致する「認定基準」を迅速に特定し、基本過失割合を提示する
Story A-1（MUST）
Summary
事故状況から「認定基準」を検索して基本過失割合を表示する
As a：損害サービス担当者（調査・示談担当）
I want：事故類型／場所／当事者種別などを入力すると、合致する認定基準と基本過失割合を取得したい
So that：紙やPDFの参照をせずに、一次回答までの時間と判断ばらつきを減らせる
Acceptance Criteria（G/W/T）
Given：ユーザーが事故属性（例：歩行者×四輪、交差点、信号有無 等）を入力している
When：検索を実行する
Then：一致度順に「認定基準カード（章・節名／要約／基本過失割合／出典）」を上位10件まで表示する
And：いずれかのカードを選択すると、基本過失割合が明示され「修正要素の適用」ステップへ遷移できる
And：該当なしの場合は「該当する認定基準が見つかりません／No results found」と表示する
Definition of Done
・検索応答 P50≤2秒、P95≤4秒で結果描画
・表示項目：章・節・見出し、要約（100–200字）、基本過失割合、出典（書籍名・版・ページ）
・監査ログ：入力条件、提示結果、選択履歴を保存
Non-Functional
・i18n（ja/EN）
・SSO（社内IdP）
・操作ログの改ざん防止（監査証跡）
Dependencies
・認定基準メタデータ（章構造・見出し）
・基本過失割合データセット（社内DBまたは抽出済み辞書）
Story A-2（MUST）
Summary
タイプアヘッド＆ファセットで候補絞り込み
As a：損害サービス担当者
I want：章／節ファセットとタイプアヘッド検索で数百件の基準から素早く絞り込みたい
So that：入力負荷を下げ、誤選択を防げる
Acceptance Criteria（G/W/T）
Given：検索フォームが表示されている
When：ファセットを選び、キーワード（日本語／英数字）を入力する
Then：候補は「前方一致→部分一致→後方一致」の順に並ぶ（日本語は五十音順ソート）
And：ヒット数を章・節ごとにバッジ表示する
And：候補0件の時は明確な空表示と次アクション（フィルタ解除／別キーワード）を提示する
DoD
・タイプアヘッド応答 P95≤150ms
・全角/半角・かな/カナ正規化
Epic B：修正要素の適用と最終過失割合の算出
Goal：基準に対して修正要素を適用し、根拠付きで最終過失割合を提示する
Story B-1（MUST）
Summary
修正要素を選択して最終過失割合をリアルタイム計算
As a：損害サービス担当者
I want：チェック式で該当修正要素を選ぶと、最終過失割合が即時計算され、根拠も表示される
So that：説明を伴う一貫した算出ができる
Acceptance Criteria（G/W/T）
Given：基本過失割合が確定している
When：修正要素（例：幼児、夜間、見通し不良 等）を選択/解除する
Then：各要素の調整率を合成し、最終過失割合を即時計算（計算式・適用順序・丸め規則を明示）する
And：結果カードに「基本割合→適用要素一覧（名称／±率／根拠出典）→最終割合」を表示する
And：PDF/CSVで根拠付き計算書をエクスポートできる
DoD
・丸め規則（四捨五入/切上/切捨）は設定で切替可能（既定＝四捨五入）
・無関係な修正要素は選択不可（基準IDとの整合性チェック）
・クリックからUI更新まで P95≤200ms
Non-Functional
・操作履歴の完全保存（誰が/いつ/何を適用）
・案件間の再現性（バージョン固定）
Epic C：AI支援による基準の自動提案
Goal：事故報告テキストから候補基準を提示し、選択時間とばらつきを低減する
Story C-1（MUST）
Summary
事故報告テキストからTop-3の推奨基準を提示
As a：損害サービス担当者
I want：事故報告（テキスト＋構造化項目）からAIの推奨基準（Top-3）を受け取りたい
So that：探索時間を短縮できる
Acceptance Criteria（G/W/T）
Given：当事者種別・場所・信号・優先関係などの項目と事故報告テキストが入力済み
When：AI推奨を実行する
Then：適合スコア付きでTop-3候補（章・節・要約・想定基本過失割合・抽出根拠ハイライト）を提示する
And：ユーザーは候補を採択、または手動検索に切替できる
And：採択結果と根拠は案件に保存される
DoD
・推奨生成 P95≤3秒
・モデル/辞書のバージョンを案件に記録（後日検証可能）
Story C-2（SHOULD）
Summary
AI提案に対する人手上書き理由を収集し、品質改善に活用
As a：チームリーダー/品質管理者
I want：AI推奨を上書きした理由を収集・集計し、モデル改善に活かしたい
So that：継続的に精度とUXを向上できる
Acceptance Criteria（G/W/T）
Given：AIがTop-3候補を提示している
When：担当者が別の基準を採択し、理由を入力する
Then：「AI候補→最終採択」「差分（章・節・割合）」「理由テキスト」を案件履歴に保存し、月次レポートで集計できる
DoD
・匿名化した利用分析ダッシュボード（件数、採択率、上書き率、代表理由カテゴリ）
Epic D：監査・エクスポート・運用基盤
Goal：説明可能性と運用性を担保する
Story D-1（SHOULD）
Summary
算出結果の監査レポートをエクスポート
As a：社内監査/品質管理
I want：入力条件・選択基準・修正要素・計算式・出典を含む監査レポートを出力したい
So that：説明可能性を担保し対外説明に耐える
Acceptance Criteria（G/W/T）
Given：案件が最終割合まで確定している
When：監査レポートを出力する
Then：PDF/CSVで「入力→検索→採択→修正→最終」の全トレイルと出典を含むレポートが生成される
And：案件ID/日時/担当者/モデル版を明記する
データ項目（抜粋）
・事故属性：当事者A/Bカテゴリ、場所（交差点/直線/駐車場/高速）、信号/標識、一時停止、優先関係、天候/時間帯
・認定基準：章、節、見出し、要約、基本過失割合、出典（書籍名・版・ページ）
・修正要素：名称、適用条件、調整率（±%）、適用順序、出典
・AI支援：候補（上位3）、スコア、抽出根拠スニペット、モデル/辞書バージョン
・監査：操作ユーザー、操作内容、時刻、前後値差分
NFR（横断）
・可用性：99.9%
・パフォーマンス：上記各P95要件を満たす
・セキュリティ：社内認証（SSO）、権限（閲覧/編集/エクスポート）、監査ログのWORM保管
・国際化：ja/EN UI、数値/日付ローカライズ
既知の制約／未確定事項（Open Questions）
1）出典の正確なページ・表番号の最終確定方法（OCR or 手入力確認）
2）丸め規則の既定値と案件単位/組織単位の上書き可否
3）AIモデルの運用枠組み（許容精度・誤提案時の運用ハンドオフ）
4）用語正規化辞書の初期充実度と更新フロー（異表記の吸収）

・A-1 / B-1 / C-1 をMUSTで実装（検索→算出→AI候補）
・A-2 / C-2 / D-1 はPhase 2（運用最適化・説明責任の強化）
